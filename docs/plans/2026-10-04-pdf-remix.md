# PDF Remix — plan

## Goal
A static web app, hosted on GitHub Pages, that lets the user:
1. remove pages from a PDF,
2. reorder pages,
3. upload more PDFs and insert a chosen set of their pages, as a group and in a chosen order, at any position,
4. preview the result,
5. download the new PDF.

**Privacy is a hard requirement:** no file or data ever leaves the browser.

## Design
- **Stack:** Vite + TypeScript, no framework. `pdf-lib` builds the output PDF; `pdfjs-dist` renders thumbnails and previews.
- **Privacy enforcement, not just intent:**
  - There's no backend. All processing happens in memory in the page.
  - The production build injects a strict Content-Security-Policy:
    `default-src 'self'`, `connect-src 'self'`, and `form-action 'none'`. Even a bug or a compromised dependency can't send data to another origin.
  - Every asset (pdf.js worker, fonts, cmaps, wasm) is self-hosted. There are no CDNs, analytics or web fonts.
  - Results open as `blob:` URLs, which exist only in this browser.
- **State model** (`src/model.ts`, pure and unit-tested). The document is an ordered list of
  `PageRef { id, sourceId, pageIndex }`. The operations are `removePages`, `movePages` (a group moves to a gap index and keeps its relative order), `insertPages`, `rangeSelect`, and an undo/redo `History`.
- **Builder** (`src/pdf.ts`, unit-tested): `buildPdf(sources, pages)` copies the pages with pdf-lib, in order. Duplicates are allowed.
- **UI** (`src/main.ts`):
  - **Workspace grid:** click, Ctrl-click and Shift-click to select. Drag and drop moves the selection; buttons cover touch devices. Delete removes pages. Ctrl+Z / Ctrl+Y undo and redo.
  - **Source panel:** pick pages from any uploaded file. They're numbered in click order, which is the insertion order. Insert them after page N, at the beginning, or at the end.
  - **Preview:** double-click a page to enlarge it. "Preview PDF" builds the real output and opens it in the browser's PDF viewer.
  - **Download:** builds the PDF and saves it.
- **Deploy:** a GitHub Actions workflow runs typecheck, lint, tests and the build, then deploys to Pages.

## Acceptance criteria
- `removePages` drops exactly the given ids and keeps the order of the rest.
- `movePages(pages, ids, gap)` puts the moved pages, in their current relative order, at the gap. The gap is counted in the original list, so dropping a group onto its own position is a no-op.
- `insertPages` clamps the index to the range [0, length].
- `rangeSelect` returns the inclusive range in either direction.
- `History` supports undo/redo, and a new push clears the redo stack.
- `buildPdf` output has the requested pages in the requested order, across several sources, including duplicates. It throws on an empty page list.
- The production `index.html` contains the CSP meta tag, and the built bundle doesn't reference any external origin.
